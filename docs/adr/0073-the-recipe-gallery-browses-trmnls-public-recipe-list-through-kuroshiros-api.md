# The Recipe Gallery browses TRMNL's public Recipe list through Kuroshiro's own API

ADR-0011 cut a Browse/Gallery UI from Recipe import v1: a searchable gallery was "a materially bigger surface (search, facets, pagination)" that "can be layered on top of the same import path later without revisiting it". #778 named it as the one thing Terminus's Extension Gallery does that Kuroshiro does not, and TRMNL's own support answer to "how do I import my extensions into Terminus" is "Extensions → Gallery, then search or endlessly scroll". This supersedes that bullet of ADR-0011; the rest of ADR-0011 and ADR-0030's Recipe Update Check stand. What trmnl.com answers was measured, not assumed:

- `GET trmnl.com/recipes.json` is unauthenticated. Query: `search` (full text, partial words and small typos, ignored under three characters), `sort-by` (`oldest`, `newest`, `popularity`, `fork`, `install`, default `newest`), `user_id`, `per_page` (default 25, maximum 100) and `page`. Each entry carries `id`, `user_id`, `name`, `description`, `published_at`, `icon_url`, `screenshot_url`, `recipe_url`, `author_bio` and `custom_fields`, plus `stats.installs` and `stats.forks`; the body carries `total`, `from`, `to`, `per_page`, `current_page`, `prev_page_url` and `next_page_url`. Searches are limited to 60 a minute per IP address, then `429`.
- `GET trmnl.com/api/categories` is unauthenticated and answers 30 slugs, `album` through `travel`.
- The authenticated `/api/recipes` endpoints exist for Recipe markup and for installing a Recipe on a trmnl.com account. Kuroshiro needs neither: markup comes from the archive at `/api/plugin_settings/:id/archive`, which ADR-0010's importer already downloads unauthenticated, and there is no account to install onto.
- `recipes.json` sends no `Access-Control-Allow-Origin`, so a browser cannot read it from the admin UI's origin.
- The list is published Recipes only. An unlisted Recipe stays out of it and is still fetched by its id.

**The public list only, so a fresh instance needs nothing configured.** No TRMNL API key, no sign-in, no setting. The cost is accepted: the list carries no `strategy`, so a Recipe the importer refuses (`static`, pending #794, or one that combines other TRMNL plugins) cannot be told apart from one it accepts until the import runs.

**Kuroshiro's API fetches the list; the browser never calls trmnl.com.** Forced by the missing CORS header, and it keeps one upstream vocabulary: the same `upstream-unreachable` the Recipe import already answers with, and a `429` worded as its own refusal because it is a *when*, not a *whether*. The read answers a wire type of Kuroshiro's own, never TRMNL's body, so a field TRMNL adds or renames does not reach the UI. All admins of one instance share its IP, and so its 60-a-minute budget.

**A category is a `#slug` token at the end of `search`, and the order is load-bearing.** The wire type keeps `search` and `category` apart, as the UI has them, and the API composes TRMNL's string as `"{search} #{category}"`. Measured: `search=%23calendar%20weather` answers 0 Recipes, `search=weather%20%23calendar` answers 8. The 30 slugs are read through a second proxied call, held in memory for an hour; when it fails the category control is not shown and search and order still work.

**The Gallery is a page of its own and the paste field stays.** `/plugins/recipes`, holding its search, category, order and carried Device in the address, so a view is linkable and survives a reload, as the Device Log's `?level=&q=` already does. Add a Plugin keeps its "Recipe" way: an unlisted Recipe is reachable only by id, and an admin who already has the id should not have to search for it. Every primary "Import a Recipe" action — the Plugins list's title action and its empty state — opens the Gallery instead of a paste field, because an admin with no Plugins yet has no id to paste.

**The Gallery orders by installs, not by TRMNL's default.** `sort-by=install` is the default here where TRMNL's API defaults to `newest`: in a catalog of hundreds, what other people actually run is the strongest signal, and `newest` surfaces whatever was published yesterday and nobody has used. `fork` is dropped from the control; forking is a trmnl.com action with no meaning on a Kuroshiro instance.

**A card hot-links TRMNL's images.** `icon_url` and `screenshot_url` are rendered as given, `loading="lazy"` so a page of 25 cards does not fetch 50 pictures at once, and `referrerpolicy="no-referrer"` so the instance's own address does not travel to TRMNL's bucket. Proxying them would mean a cache, a size cap and a host allowlist so Kuroshiro does not ship an open image proxy — real machinery for a partial privacy gain, given that the admin asked to browse TRMNL's catalog. The consequence is accepted: the pictures need a browser with internet access, and a browser without one still gets readable cards.

**Importing from a card is the import that already exists.** The same call the paste field makes, with the Recipe's id and the carried Device, and the Plugin's page opens on success. No preview step: the import produces an ordinary editable Plugin, the Plugin page is its detail view, and a wrong one is deleted in a click. A card whose Recipe a Plugin already holds says so, in Add a Plugin's wording, and importing again is still allowed.

## Consequences

- The Gallery holds nothing and stores nothing. It adds no entity, no column and no migration; the only persisted trace of it is the source Recipe id every import has written since ADR-0010.
- trmnl.com being down, slow or over its rate limit is a refusal on one page, not a failure anywhere else. Nothing in Kuroshiro polls it on a schedule.
- The admin UI's test suite does not reach trmnl.com: the page spec fakes Kuroshiro's own read, and the screenshot baselines fake the image requests with the pinned image, so a Recipe author re-uploading a screenshot cannot move a baseline. There is deliberately no `real-api/` journey through the Gallery — that suite would then depend on TRMNL's uptime.
- Additive follow-ups: the authenticated `/api/recipes` endpoints if pre-warning about a refused strategy ever matters, a Recipe's own page inside Kuroshiro, and the `user_id` filter as an "more by this author" link.
