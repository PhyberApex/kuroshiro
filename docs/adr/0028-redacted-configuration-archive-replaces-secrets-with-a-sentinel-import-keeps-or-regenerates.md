# Redacted Configuration Archive: secrets become one sentinel, Configuration Import keeps the target's value or regenerates it

ADR-0021 exported every secret in plaintext and left "opt-in secret redaction" as an additive follow-up. Issue #1029 picks that up: Configuration Export gains a redact-secrets option so an archive can be shared, diffed, or kept somewhere that must not hold credentials. Triage settled five decisions the issue left open or did not see.

- **A missing value on import is accepted with a warning, not refused.** When Configuration Import meets the sentinel and the target holds no value to keep — a fresh instance, or a record the target has never had — it imports the record anyway and appends a per-record warning to the import summary, the same way it already reports a Palette, Device Model or Firmware it could not resolve. The alternative, refusing the whole archive as the `schemaVersion` mismatch does, would make a redacted archive useless anywhere but the instance it came from, which defeats the point of exporting one; a per-record skip would leave dangling references (a Screen whose Device was skipped). A degraded restore the admin can read about is better than none.
- **The redacted set is everything mechanically identifiable as a credential.** Data Source header values, Device `apikey` and `mirrorApikey`, Plugin Variables flagged `isSecret`, and Plugin Webhook Tokens. The issue named only the first three; the archive also carries the last two in plaintext. Data Source `url` and `body` are not redacted — an API key embedded in a query string cannot be told apart from any other string — and the export surfaces say so.
- **Every header value is redacted, keys stay.** Guessing which header names carry auth (`Authorization`, `X-Api-Key`, …) would miss custom ones, and the keys are what a reader of the archive needs to understand the Data Source. A redacted archive still shows *which* headers a Data Source sends, never what.
- **Redaction is a Configuration Export option only.** The per-Plugin `.trmnlp` export keeps writing headers verbatim, so the two exports stay consistent by default and the shared `.trmnlp` layout is untouched. The cost: a `plugins/<id>/` folder pulled out of a *redacted* archive and imported through the per-Plugin path lands the sentinel as a literal header value, because that importer knows nothing about redaction. Extending the sentinel handling to the per-Plugin importer is a follow-up.
- **No `schemaVersion` bump.** The manifest's `containsSecrets` becomes `false` on a redacted archive and a sibling `redacted: true` is added; the sentinel is an ordinary string in the same fields. Both are additive, so an unredacted archive keeps the exact shape it has today and #1025's bump to 2 is unaffected.

## Consequences

- The sentinel is one fixed, unmistakable string (of the form `__KUROSHIRO_REDACTED__`) that is never a plausible real value; Configuration Import compares against it in every redactable field regardless of whether the manifest says the archive is redacted, so a hand-edited archive behaves the same as an exported one.
- On import, a sentinel resolves as: keep the target row's current value when the row exists (by `id`, or for a Device by `mac`) and that value is set; otherwise fall back per field — a header is dropped, a secret Variable's value becomes empty, `mirrorApikey` becomes unset, a new Device is given a freshly minted `apikey` as auto-registration would, and a Webhook Token is regenerated. Each fallback appends one warning naming the record and field. A regenerated `apikey` or Webhook Token means the corresponding hardware or external sender has to be re-paired; the warning says so.
- `containsSecrets` and `redacted` are mutually exclusive on the manifest: an archive is one or the other, never both.
- The export UI and the `X-Kuroshiro-Contains-Secrets` response header reflect the choice: the credentials warning and the header are only present when the archive actually contains secrets.
- Data Source `url` and `body` remain a leak vector on a redacted archive; the UI copy names them so an admin who embeds a key in a query string is not misled.
- Follow-ups that stay additive: sentinel handling in the per-Plugin `.trmnlp` importer, a per-field "was redacted" marker richer than the sentinel, prompting for secrets at import time.
